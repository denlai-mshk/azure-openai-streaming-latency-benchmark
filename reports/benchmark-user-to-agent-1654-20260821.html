3. Measurement contract

This is not isolated inference time. Client-observed latency includes network transport, Azure front-end processing, queueing, prompt ingestion, model work, and response transfer. Authentication occurs before the per-request timer.

Thinking estimate is TTFT: request start to first visible content. Composing estimate is TTLT minus TTFT: first to final visible content.

The stacked timing total is TTLT. TTFT is both the first milestone and the thinking segment; it is not added a second time.

Measured iterations select queries in template order and cycle through the query pool when necessary. Reported statistics show average, P95, P99, and maximum latency over response-ready iterations. The warm-up call is recorded in rawdata/raw-results.jsonl for audit but excluded from stats.

5. Customizing the sample templates

Edit the YAML template files to model your own workload:

  • prompt-template-routing.yaml — Query routing
  • prompt-template-reasoning.yaml — Reasoning

Templates define metadata, request controls, the system prompt, queries, and an optional validation.schema. A response is ready only after it satisfies the configured schema. Structural validation does not evaluate semantic correctness.

Source artifacts: rawdata/raw-results.jsonl, rawdata/summary.json, rawdata/benchmark.log, benchmark.py. Response-ready latency is client-observed end-to-end time, not isolated model inference.
